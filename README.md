# contract-validation

Доменная библиотека финансовых проверок для документов закупки: контроль
сумм, НДС, авансов, спецификаций и предельных цен.

Зависит только от стандартной библиотеки Python. Интеграция с приложением —
через порты (`ports/`).

## Задача

В закупочном документе одни и те же суммы повторяются в разных местах: итог
договора, спецификация, график платежей, авансы, строки НДС, сумма прописью.
Значения расходятся из-за округлений, разных баз НДС («в том числе» против
«кроме того») и процентов аванса, не совпадающих с фактическими суммами.

Библиотека формализует такие расхождения как набор независимых проверок,
каждая возвращает структурированные ошибки с указанием места в документе, а
не текстовое сообщение.

## Устройство

```
src/contract_validation/
├── entities/   финансовые модели и поля с привязкой к источникам
├── checks/     проверки + механизм объявления зависимостей
├── merge/      слияние значений из нескольких документов
└── ports/      интерфейсы к внешним сервисам
```

### Финансовые модели

`Money`, `Vat`, `Payment`, `TotalAmount` — неизменяемые датаклассы с
арифметикой на `Decimal`. `Payment` знает собственный режим НДС
(`VatInclusion`: `INCLUDED`, `EXCLUDED`, `UNSPECIFIED`, `MIXED`), поэтому
суммы с разной базой приводятся к общему виду до сравнения, а не
складываются напрямую.

`ComparisonResult` по конструкции не может содержать расхождение при
успешном статусе:

```python
@dataclass(frozen=True, kw_only=True)
class ComparisonResult[TDiscrepancy]:
    status: ComparisonStatus
    discrepancy: TDiscrepancy | None = None

    def __post_init__(self) -> None:
        has_discrepancy = self.discrepancy is not None
        if (self.status is ComparisonStatus.NOT_OK) != has_discrepancy:
            msg = "only a NOT_OK comparison may contain a discrepancy"
            raise ValueError(msg)
```

### Объявление зависимостей

Проверка объявляет нужные поля декларативно: `Requires` требует ровно одно
поле данного типа, `OptionalDep` допускает отсутствие.

```python
class CheckTotalAmountsValidation(BaseCheck):
    total_amount_field = Requires(TotalAmountField)
    advance_payments_field = OptionalDep(AdvancePaymentsField)
```

`prepare()` разрешает объявления по набору извлечённых полей. Если
обязательного поля нет или их несколько, поднимается
`MissingRequiredFieldError` или `MultiplyRequiredFieldError` — вызывающий
код отличает «нет данных для проверки» от «проверка не прошла».
Поддерживается и `Requires(list[TaxField])`.

### Привязка ошибок к документу

Каждое поле хранит `sources` — документы и заголовки, откуда взято
значение. Ошибка несёт `FieldLocation` с именем поля и путём внутри него,
поэтому расхождение показывается пользователю в контексте.

Иерархия ошибок типизирована: `BaseAmountDiscrepancyError` несёт значение,
эталон и разницу, `BaseNormalizedAmountDiscrepancyError` — дополнительно
операнды и целевой режим НДС, то есть сохраняет, из чего сложилась сумма и
к какой базе её приводили.

### Слияние данных из нескольких документов

`MergeRegistry` выбирает обработчик по типу значения: скаляр, строка,
список, датакласс — рекурсивно по полям. Расхождения собираются в
`ValuesDiscrepancyError` с точным путём (`value.vat.rate`). `Decimal`
сравнивается с допуском, строки нормализуются (регистр, пробелы, `ё`/`е`),
для платежей действуют обработчики с учётом режима НДС.

## Состав проверок

| Проверка | Что контролирует |
| --- | --- |
| `CheckTotalAmountsValidation` | сумма строк НДС и авансов против итога договора |
| `CheckPriceValidation` | расчёт стоимости позиций и их сумма против итога |
| `CheckVatCalculation` | НДС по формуле для указанной ставки и базы |
| `CheckTotalAmountUpperBoundVatCalculation` | то же для предельной цены |
| `CheckTaxRatesValidation` | согласованность ставок НДС между платежами |
| `CheckPaymentPercentValidation` | проценты авансов и их суммы |
| `CheckValuesValidation` | положительность сумм, ставок и сумм НДС |
| `CheckTotalAmountUpperBound` | итог договора против предельной цены |
| `CheckNumberTranscriptionRub` | сумма прописью против числового значения |

## Пример

```python
from decimal import Decimal

from contract_validation.checks.check_price_validation import CheckPriceValidation
from contract_validation.entities import FieldCollector

check = CheckPriceValidation(tolerance=Decimal("1"))
check.prepare(FieldCollector([spec_positions_field, total_amount_field]))
result = await check.execute()

for error in result.errors:
    print(error.error_type, error.location)
```

## Происхождение кода

Модуль выделен из закрытого проекта автоматизации проверки закупочной
документации, с разрешения правообладателя. Перенесена история коммитов
только относящихся к нему файлов, поэтому в `git log` есть коммиты других
участников команды. Их коммиты сохранены, но имена и адреса заменены на
обезличенные псевдонимы (`Contributor A`, `Contributor B` и далее),
чтобы не публиковать персональные данные без согласия.

Это командный код. Около трёх четвертей строк в текущем срезе — мои:
финансовые модели и арифметика с режимами НДС, декларативный механизм
объявления зависимостей, типизированные расхождения с привязкой к
источникам, большинство реализаций проверок и их тесты, обработчики слияния
платежей. Архитектурный каркас модуля и часть базовых классов
(`entities/field.py`, `checks/errors.py`, `entities/errors/base.py`,
`entities/validation.py`, `ports/`) написаны коллегами и включены потому,
что без них модуль не работает.

При выделении удалены привязки к инфраструктуре исходного приложения
(pipeline, репозитории, брокер сообщений, логирование), тестовая обвязка
переписана на прямой вызов проверок, данные в тестах заменены
синтетическими.

Репозиторий опубликован как демонстрация инженерных решений, а не как
библиотека для повторного использования. Файл лицензии отсутствует:
исключительные права на исходный проект принадлежат заказчику, часть строк
написана другими участниками команды. Разрешение на копирование, изменение
и распространение не предоставляется.
